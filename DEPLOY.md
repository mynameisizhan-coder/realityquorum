# Deploying RealityQuorum

One Node process serves both the built React app and the API on a single port. Data (SQLite database + uploaded files) lives in one folder that must be on persistent storage.

## Quick start

### Docker (recommended)
```bash
docker build -t realityquorum .
docker run -d --name realityquorum -p 8080:8080 \
  -e SESSION_SECRET="$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")" \
  -e GEMINI_API_KEY="your-key" \
  -v realityquorum-data:/data \
  realityquorum
```
Open http://localhost:8080. Health check: `GET /api/health`.

### Without Docker (any host with Node 24+)
```bash
npm ci
npm run build
NODE_ENV=production SESSION_SECRET=... GEMINI_API_KEY=... RQ_DATA_DIR=/var/lib/realityquorum npm start
```

### Render (current public demo)
`render.yaml` defines the service. In Render: **New → Blueprint**, pick this repository, paste `GEMINI_API_KEY` when asked, **Apply**. `SESSION_SECRET` is generated by Render. Every push to `main` redeploys.
- Free plan: the service sleeps after 15 minutes idle (about a minute to wake) and has no persistent disk, so cases reset to the two demo cases on each redeploy or restart. For lasting data, switch to a paid plan and add a disk mounted at `/data`.

### Hosting notes
- Works on any platform that runs a Docker image or Node 24 with a **persistent disk** (Render, Railway, Fly.io, a VM). Serverless platforms without a persistent disk are **not** suitable: SQLite and uploads would be lost.
- Run **one instance**. SQLite on a local disk does not support several instances sharing data.
- Put it behind HTTPS (most hosts do this automatically). Cookies are `Secure` in production.

## Environment variables
| Variable | Required | Default | Notes |
|---|---|---|---|
| `NODE_ENV` | yes | — | `production` (the Docker image sets it) |
| `SESSION_SECRET` | recommended | generated | ≥ 32 random characters. If unset, a random secret is generated once and stored in the data folder |
| `GEMINI_API_KEY` | no | — | Without it the offline mock is used |
| `GEMINI_MODEL` | no | flash-lite (text), 3.7-flash (photos) | Comma-separated, tried in order |
| `PORT` | no | 8791 (8080 in Docker) | |
| `HOST` | no | `0.0.0.0` in production | |
| `RQ_DATA_DIR` | no | `server/data` (`/data` in Docker) | Database + uploads; must persist |
| `COOKIE_SECURE` | no | on in production | Turn off only for plain-HTTP testing |
| `TRUST_PROXY` | no | on in production | Needed for correct rate limiting behind a proxy |
| `RATE_LIMIT_PER_MINUTE` | no | 60 | Per client, on Gemini-backed and write endpoints |
| `ALLOW_DEMO_LOGIN` | no | true | Role switcher; see the warning below |

> **Demo login warning.** With `ALLOW_DEMO_LOGIN=true` anyone who opens the site can act as any role, including operator and trust officer. That is right for a hackathon demo and wrong for real reports. Set it to `false` once real authentication exists.

## Backups
Back up `RQ_DATA_DIR` (the `.db`, `.db-wal`, `.db-shm` files and `uploads/`). For a consistent copy, stop the app or use `sqlite3 realityquorum.db ".backup backup.db"`.

## Reset demo data
Sign in as the operator demo account and call `POST /api/demo/reset`, or delete the data folder and restart.
